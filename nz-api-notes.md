# nz.ua — нотатки по бекенду (для написання парсера)

Дата аналізу: 2026-09-01. Аналізувалась сторінка щоденника (`/schedule/diary`) залогиненого користувача через DevTools Network + інспекцію DOM. Дій запису/зміни даних не виконувалось.

## 1. Загальна архітектура

**Це НЕ SPA з JSON API — це класичний SSR (server-side rendered) сайт.**

- При завантаженні сторінки жодних XHR/fetch-запитів з JSON не відбувається (перевірено через Network tab на кількох переходах — щоденник, зміна тижня, зміна семестру).
- Кожна зміна стану (тиждень, семестр, учень) — це **повна навігація на новий URL** із query-параметрами. Сервер рендерить готовий HTML і віддає його одним документом.
- Знайдений `<meta name="csrf-param" content="_csrf">` — це дефолтне ім'я CSRF-параметра фреймворку **Yii2 (PHP)**. Бекенд майже напевно на Yii2.
- Немає жодного великого вбудованого JSON-блоба в `<script>` тегах (найбільший інлайн-скрипт — 3.5KB, схоже на аналітику/конфіг, не дані сторінки).

**Висновок для парсера:** інтегруватись треба через HTML-скрейпінг (запит сторінки з валідними cookies сесії → парсинг DOM), а не через окремий API-ендпоінт.

## 2. Автентифікація

- Стандартна форма логіну на `/` (POST, ім'я користувача/e-mail + пароль), CSRF-токен обов'язковий (`_csrf` в meta-тезі й формі).
- Після логіну — сесія на cookies (PHPSESSID або аналог Yii2 `_identity`/`_csrf` cookies). Токенів у заголовках (Bearer тощо) не виявлено.
- Для парсера: логінитись один раз, зберігати cookie jar, переоформлювати запити з тими ж cookies.

## 3. Ключові URL / query-параметри

### Щоденник (уроки + ДЗ + оцінки)
```
GET https://nz.ua/schedule/diary?start_date=YYYY-MM-DD&student_id=<ID>&type=for-school
```
- `start_date` — понеділок потрібного тижня (сторінка показує весь тиждень одразу)
- `student_id` — числовий ID учня (напр. `12345678`) — потрібен, якщо в акаунті батьків декілька дітей
- `type=for-school` — можливо є інші значення (не досліджено)
- Без query-параметрів `/schedule/diary` показує поточний тиждень для дефолтного учня

### Семестр
Обирається окремим select/dropdown у шапці сторінки — при виборі теж повна навігація (не досліджено точний query-параметр, схоже семестр зберігається в сесії/cookie після вибору, бо URL при зміні семестру не завжди явно містив параметр семестру).

### Додавання відповіді на ДЗ (НЕ викликалось, лише знайдено href)
```
/hometask/add-answer?schedule=<ID>&class=<ID>&student_id=<ID>
```
Посилання з'являється на кожному уроці з незданим ДЗ (червона позначка "ДЗ").

## 4. Структура HTML щоденника (класи для селекторів парсера)

```
DIV.diary-item                              — один день
  P.diary-item__title                       — текст "понеділок, 2 березня"
  DIV.diary-box                             — один урок (повторюється)
    DIV.diary-item__data
      SPAN.diary-item__num                  — номер уроку "1."
      SPAN.diary-item__time                 — час "08:3009:15" (start+end зліплені, розділені <br>)
    DIV.diary-item__content
      DIV.diary-lesson
        DIV.diary-lesson-box
          P.diary-item__label               — назва предмету, напр. "Географія"
            SPAN (inline style)             — опційно: "заміна" якщо є заміна вчителя
          SPAN.diary-item__cabinet          — кабінет/корпус, напр. "214"
        DIV.diary-lesson-content
          DIV.diary-lesson-row              — повторюється (тема уроку, оцінка, ДЗ — окремі рядки)
            DIV.diary-lesson-text
              P                             — текст: "Поточна: <тема уроку>" АБО "Д/з: <текст ДЗ>"
            DIV.diary-add                   — опційно, поруч з темою уроку:
              SPAN.diary-add-green.point-<N>  — оцінка (клас містить бал, напр. point-10, point-8, point-9)
              — АБО —
              SPAN.diary-add-red + A[href]="ДЗ" — незакрите ДЗ, посилання на /hometask/add-answer
```

### Приклад витягнутих даних (структура реальна, з навчального дня 2 березня 2026; кабінет, оцінка та ID учня замінені вигаданими значеннями, прізвище прибране)

```json
{
  "date": "2026-03-02",
  "day_label": "понеділок, 2 березня",
  "lessons": [
    {
      "number": "1",
      "time": "08:30-09:15",
      "subject": "Географія",
      "cabinet": "214",
      "topic": "Транспорт та його роль у національній економіці.",

    },
    {
```

Поля теми/ДЗ — вільний текст, іноді містить згадку підручника/сторінки прямо в реченні (напр. "Опрацювати с. 164"), єдиного окремого поля "підручник"/"сторінка" в розмітці немає — це частина тексту ДЗ, який писав вчитель, парситься лише евристикою (regex на "ст.\d+" / "с. \d+" тощо), не гарантовано.

## 5. Оцінки

Клас `diary-add-green.point-<N>` — оцінка N вшита прямо в class (не тільки в тексті), зручно для парсингу без читання тексту. Колір класу (green/red/інший — не перевірено весь діапазон) може кодувати тип/діапазон оцінки.

## 6. Що не досліджено (для наступного разу)

- Точний механізм зміни семестру (query-параметр чи сесія/cookie)
- Чи є окремий ендпоінт для списку учнів (для батьківського акаунту з кількома дітьми)
- Реальний запит на `/hometask/add-answer` (не виконувався — це запис даних)
- Заголовки відповіді сервера (Server, X-Powered-By) — не вдалось зняти через безпечний fetch у DevTools (JS-обмеження навколо cookie-даних у зчитуючому інструменті)
- Мобільний/AJAX API (можливо існує окремий ендпоінт для мобільного застосунку nz.ua — не перевірялось, вебверсія його не використовує)

## 7. Практичний висновок для парсера

Найпростіший робочий підхід:
1. Логін через `requests`/`httpx` сесію з парсингом CSRF-токена з форми логіну
2. Циклом по тижнях: `GET /schedule/diary?start_date=<понеділок>&student_id=<ID>`
3. Парсинг HTML через BeautifulSoup/lxml за селекторами з розділу 4
4. Кешування cookies між запусками, щоб не логінитись щоразу
